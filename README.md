# linux-C-develop
不可靠信号对应 Linux 中 1-31 号信号（也叫 “传统信号”/“非实时信号”），是早期 UNIX 信号机制的延续，核心问题是信号可能丢失。

2. 核心特点（“不可靠” 的原因）
    
    无排队机制：如果同一个不可靠信号多次发送（比如短时间内发 3 次 SIGINT），进程只能收到 1 次，剩余的会被丢弃（内核不记录发送次数）。
    
    信号处理后可能恢复默认行为：早期 signal() 函数注册的处理函数，在信号触发后会自动恢复为默认行为（需重新注册），sigaction() 可通过 sa_flags 避免此问题。
    
    不支持携带附加数据：只能通知进程 “有这个信号”，无法传递额外信息。

可靠信号对应 Linux 中 32-64 号信号（也叫 “实时信号”），是 POSIX.1b 为解决不可靠信号的缺陷而扩展的，核心优势是信号不丢失。

2. 核心特点（“可靠” 的原因）

    支持排队机制：如果同一个实时信号多次发送，内核会为其排队，进程会按发送顺序依次接收所有信号（不会丢失）。
    
    信号处理行为稳定：不会自动恢复默认行为，无需重复注册。
    
    支持携带附加数据：可通过 sigqueue() 发送信号时携带自定义数据，配合 sigaction 的 SA_SIGINFO 标志接收数据。
